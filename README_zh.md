# OPM MIDI 离线渲染器

> **语言**: [[English](README.md) | 简体中文]

本项目是一个轻量级、高性能的离线 MIDI 转 WAV 合成器，基于 **Nuked OPM**（周期精确的 YM2151 模拟器）构建。受经典 PC-98 `NECOPN.DRV` 驱动器的动态声部抢占（丢音）机制启发，本渲染器严格将播放限制在 8 个硬件通道（YM2151 的物理上限）内，并还原 90 年代 FM 音效芯片真实而怀旧的听感。

> **🎯 状态**: 离线渲染器功能完整，包含硬件级精确的 YM2151 模拟、NECOPN 风格声部抢占、硬件 FM 鼓合成以及 CC74 亮度控制。WOPN 银行互操作性已通过验证。
> 
> **📦 开箱即用**: 已内置默认 `NECOPN_GM.opm` 音色银行（从逆向工程还原的 `NECOPN.DRV` 中动态提取）。无需准备外部银行即可直接渲染。

## 🏗️ 架构与核心要点

**1. 周期精确的 YM2151 模拟**
由 C 语言编写的 Nuked OPM 核心驱动，每个采样模拟 64 个时钟周期。这是一个 CPU 密集型模拟器，但 Python 封装层已高度优化。

**2. 动态声部抢占（NECOPN 风格）**
渲染器严格限制在 8 个硬件通道内。当复音数超过硬件上限时，"大逃杀"声部抢占算法会优先保留主旋律，并激进地切断较旧或较低优先级的音符——模拟原始 `NECOPN.DRV` 驱动器的真实丢音行为。

**3. 硬件 FM 鼓合成**
由于 YM2151 不支持 ADPCM/采样播放，GM 标准鼓组（通道 10）通过纯 FM 硬件噪声和超快包络合成。一个物理通道（Ch 7）专供打击乐使用，完全豁免于声部抢占算法。

**4. CC74 亮度控制**
按照 Wohlstand 的方案（libOPNMIDI）实现 CC74（亮度）：动态调整调制器 TL，以模拟 FM 音色上的低通滤波效果。

**5.跨芯片翻译引擎（Translation Engine）**
由于历史上从未存在过原生的 128 音色 OPM GM 音色库，当前市面上所有的 .opm 预设（包括 NECOPN_GM）本质上都是基于 OPN 芯片参数转换而来的。将 OPN 参数直接输入 OPM 会导致物理音高偏移以及鼓声的“塑料放屁音”。为此，本引擎内置了 translator.py 翻译层：

音高翻译（默认开启）：基于 440Hz 标准，将 MIDI 音符通过数学公式精确转换为 OPM 的 KC/KF 寄存器值，彻底消除历史遗留的音高偏移。

旋律包络翻译（默认开启）：将旋律的衰减率（DR/SR）适当放缓，防止音符在 OPM 硬件上干瘪刺耳。

鼓组包络（绝对不翻译）：鼓组直接使用 OPN 原生的极速包络，以保证在 OPM 硬件上拥有极短的瞬态。如果对鼓组进行包络翻译，会导致鼓声拖泥带水，在 VGM 播放器（HLE 核心）中更是会糊成低沉的“撅”声。

(注：可通过 -r 或 --raw 参数关闭翻译层，体验原汁原味的物理偏移与原生畸变)

## 📦 必需资源

1. **Python 3.8+**
   * 运行 Python 引擎所需。
2. **Nuked OPM 核心（`opm.dll` / `opm.so`）**
   * 编译好的 C 核心必须放置在根目录中。请注意，Nuked OPM 是 CPU 密集型的周期精确模拟器，渲染速度取决于你的 CPU。
3. **音色银行（`.opm`）**
   * 默认的 `NECOPN_GM.opm` 已内置，从逆向工程还原的 `NECOPN.DRV` 中动态提取。
   * *（可选）* 也可以使用任何有效的 `.opm` 银行，包括由 WOPN 转换而来的银行（见下文）。

## 🚀 快速开始

### 将 MIDI 文件渲染为 WAV
bash
python player.py "path/to/your.mid" --bank "NECOPN_GM.opm" -o "output.wav"

命令行参数
参数	默认值	说明
midi	—	输入 MIDI 文件的路径。
--bank	NECOPN_GM.opm	.opm 音色银行的路径。
-o, --out	—	输出 .wav 文件的路径。
--tail	1.0	结尾额外渲染的音频秒数。
--clock	3579545	OPM 芯片的主时钟（Hz）。

## 鼓组实现与OPM音色库限制
标准.opm文件格式的一个根本性局限在于，它原生仅支持128种旋律乐器。历史上，OPM芯片上的打击乐器完全是合成的，或者通过外部硬件来处理。因此，标准的.opm音色库在物理上无法包含一个GM鼓组。

为了解决这个问题并保持真实的节奏，该引擎通过以下逻辑实现鼓组：

**1. WOPN 回溯**：我们从标准的 WOPN 库中提取了一套经过专业调音的 GM 打击乐器组。
硬编码在驱动器中：由于 .opm 无法存储鼓组，这些调音参数被直接硬编码到 driver.py 中作为一个专用的字典（DRUM_BANK）。这绕过了 .opm 格式的限制，并避免了为每次击鼓动态加载音色所带来的性能开销。

**2. 第7通道的用途**：为了保留7个旋律通道用于复调（通过NECOPN声音窃取算法），整个鼓组被锁定在物理通道7。这导致了一种“单音复调妥协”，即重叠的鼓音（例如底鼓和踩镲同时敲击）会相互切断，忠实地复制了老式硬件的物理限制。

提示：遗留 FM 噪声鼓：原始的手工 FM 噪声鼓逻辑被保留在代码中作为“遗留回退”。

### 🔄 与 WOPN 音色库的互操作性
本引擎不仅限于从 `NECOPN.DRV` 中提取的 `.opm` 预设。为 `libOPNMIDI` 设计的有效 **`.wopn`（WOPN2-B2NK）** 银行在转换为 `.opm` 格式后，也可以被本引擎完美使用。

1. **获取 WOPN 音色库**：可在 [libOPNMIDI 仓库](https://github.com/Wohlstand/libOPNMIDI) 中找到各种乐器库。
2. **获取 OPN2-BE**：下载 [OPN2BankEditor](https://github.com/Wohlstand/OPN2BankEditor) 的 **DEV（开发）版本**，以确保获得最新的 WOPN 解析和 OPM 导出支持。
3. **转换为 OPM**：在 OPN2-BE 中打开 `.wopn` 文件，并导出为 `.opm` 预设音色库。
4. **渲染**：运行 Python 引擎，并通过 `--bank` 指定转换后的 `.opm` 文件。

### 🔄 VGM 导出支持
除了渲染 WAV 格式外，本项目还提供了一个专用的导出工具：vgm_player.py，允许你将 MIDI 导出为标准的 VGM (Video Game Music) 格式。

1. **为什么要导出为 VGM？**：VGM 文件仅记录原始的 YM2151 寄存器指令和时间戳，因此体积非常小（例如，一首 4 分钟的曲子可能只有几十 KB）。你可以使用现代 VGM 播放器（如安装了 VGM 插件的 Foobar2000 或 VGMPlay），甚至是在真实的硬件音源板上播放它们。
2. **如何使用**：请使用 vgm_player.py 进行导出。除了输出格式不同外，其余的逻辑（音色库读取、NECOPN 大逃杀抢音、纯 FM 鼓组）与 WAV 导出完全一致，无任何区别。

python vgm_player.py "你的文件.mid" --bank "NECOPN_GM.opm" -o "输出.vgm"

### 🧪 实验性功能：OPMMIDI-GAI 双芯片版本（FM + PCM）
位于 experimental/OPMMIDI-GAI/ 目录下。这是一个技术验证（PoC），灵感源自 夏普 X68000 的硬件架构（FM+PCM） 以及 富士通 FM TOWNS 上 EUPHONY（尤弗乐）驱动的混合分离概念。

1. **架构理念**：正如 EUPHONY 驱动将音源分为 FMB（FM音色库用于旋律） 和 PMB（PCM音色库用于节奏），本引擎将工作负载彻底分离。Nuked-OPM 核心负责驱动 8 个物理通道全力演奏 FM 旋律，而外挂的虚拟 PCM 核心专门负责复音打击乐。

2. **移除 FM 鼓**：此实验版本中彻底删除了历史遗留的硬编码 FM 鼓组，所有打击乐严格交由 PCM 核心处理。

3. **专注 WAV 渲染**：该版本仅用于 WAV 渲染输出。由于双芯片 VGM 数据块封装尚未完善，VGM 导出功能已主动移除。

3. **测试要求（版权警告）**：因 Yamaha 版权原因，用户必须自备 OPNA 的 RHY 采样文件（命名为 2608_BD.WAV、2608_SD.WAV 等），并将其放置在 experimental/OPMMIDI-GAI/ 文件夹内（与实验版 player.py 同级），才能听到完整的节奏声部。

注：这是实验性分支，不影响主分支纯血单芯片 OPM 引擎的运行。

###
- **硬件特性与不可控伪影：** 由于本项目使用 Nuked OPM，它模拟的是 YM2151 芯片的原始数字输出，没有现代 DSP 平滑或内置低通滤波器。因此，密集的 MIDI 事件或高反馈音色可能产生刺耳的"拉链噪声"或高频混叠。这是硬件的真实特性，而非 bug。
- **替换核心：** 如果你偏好更平滑、VST 般的听感，本项目的模块化设计允许你替换核心。参考 `core.py` 中的封装逻辑，实现 `ChipCore` 抽象类以包装其他模拟器（如 `fmgen`），然后传递给 `driver.py`。

### 🔬 技术细节
- **周期精确核心：** Nuked OPM 每个采样模拟 64 个时钟周期的 YM2151。
- **声部抢占：** 8 通道硬限制，基于优先级的丢音策略，与 `NECOPN.DRV` 行为一致。
- **鼓通道保留：** 物理通道 7 专供 FM 打击乐使用，不参与声部抢占。
- **CC74 亮度：** 按照 libOPNMIDI 的实现调整调制器 TL。
